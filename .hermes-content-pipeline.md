# Content Automation Pipeline - Hermes Guide

This document describes the new deterministic pipeline for adding and maintaining review content on homeofficestack.com.

## The Problem We're Solving

When adding a new review, Hermes sometimes:
- Uses wrong Amazon tag
- Forgets required sections
- Has inconsistent formatting
- Misses JSON-LD schema
- Leaks the old brand name "Budget Tech Picks"

**Solution:** A pipeline that catches these errors before they go live.

## The Pipeline

```
Hermes (content) 
    → generate-review.sh (template)
    → Hermes fills placeholders
    → validate-review.sh (checks)
    → publish-review.sh (if passes) OR flag to Don (if fails)
```

## Step-by-Step Workflow

### For NEW Reviews

**Step 1: Generate the review file**
```bash
cd ~/budget-tech-picks
./scripts/generate-review.sh \
  <filename.html> \
  PRODUCT_NAME="<Full Product Name>" \
  ASIN="<Amazon ASIN>" \
  CATEGORY_SLUG="<category-slug>" \
  CATEGORY_NAME="<Category Name>" \
  PRICE="<price>" \
  RATING="<1-5>"
```

**Example:**
```bash
./scripts/generate-review.sh \
  ergotron-lx-monitor-arm.html \
  PRODUCT_NAME="Ergotron LX Monitor Arm" \
  ASIN="B00JQB4N8G" \
  CATEGORY_SLUG="monitor-arms" \
  CATEGORY_NAME="Monitor Arms" \
  PRICE="$129.99" \
  RATING="4.7"
```

This creates a file with placeholders like `[Hermes: Write about what you liked]`.

**Step 2: Fill in the content**
Edit the file and replace placeholders with actual content. Be thorough but don't worry about structure — the template enforces that.

**Step 3: Validate before publishing**
```bash
./scripts/validate-review.sh reviews/<filename.html>
```

If this fails, fix the reported errors before proceeding.

**Step 4: Publish**
```bash
./scripts/publish-review.sh reviews/<filename.html> "Add review: <Product Name>"
```

This:
1. Runs validation
2. If passed: commits and pushes to GitHub Pages
3. If failed: reports errors and does NOT publish

### For EXISTING Reviews (Maintenance)

**Daily checks run automatically via cron.** If issues are found, fix them:

1. **Dead ASIN check:** Navigate to Amazon page in browser, check for "Page Not Found"
2. **Update ASIN:** If product moved, find new ASIN and update:
   - HTML affiliate link: `https://www.amazon.com/dp/<NEW_ASIN>?tag=homeofficestack-20`
   - JSON-LD schema: update the `"sku": "<NEW_ASIN>"`
   - Product image URL if needed

3. **Price accuracy:** Get live price via browser:
   ```javascript
   document.querySelector('.a-price .a-offscreen')?.innerText
   ```
   Update price in review metadata section.

4. **After any edits, always validate:**
   ```bash
   ./scripts/validate-review.sh reviews/<filename.html>
   ```

5. **If validation passes, commit:**
   ```bash
   cd ~/budget-tech-picks
   git add reviews/<filename.html>
   git commit -m "Update: <change description>"
   git push origin main
   ```

## What Validation Checks

| Check | Error if missing |
|-------|------------------|
| DOCTYPE + UTF-8 | Blocks HTML rendering |
| Meta description | Blocks SEO |
| Title format | Blocks SEO |
| JSON-LD Review schema | Blocks rich snippets |
| ASIN in schema | Blocks Amazon attribution |
| Amazon tag `homeofficestack-20` | Blocks affiliate tracking |
| Old tag `budgettechp08-20` | **Blocks publishing entirely** |
| Brand name `Home Office Stack` | Must be present |
| Old brand `Budget Tech Picks` | **Blocks publishing entirely** |
| Affiliate disclosure | Legal requirement |
| Required sections | Must have all 5 sections |

## Error Handling

If validation fails:
1. Read the error messages
2. Fix each error in the HTML file
3. Re-run validation
4. Only publish when 0 errors

**Never bypass validation.** If something can't be fixed automatically, flag to Don:
> "Validation failed for <review>. Issues: <list>. Needs manual review."

## Critical Rules

1. **Tag must be `homeofficestack-20`** — nothing else
2. **Never mention "Budget Tech Picks"** — new brand is "Home Office Stack"
3. **Always validate before commit**
4. **Always use the template** — don't write HTML from scratch
5. **Missing sections = fail** — every review needs: Our Verdict, Specifications, What We Liked, What Could Be Better, Bottom Line

## Adding a New Product — Complete System

When Content Automation approves a new product, Don says YES, and the following happens:

### Step 1 — Add to featured-products.json

Add the new product's full data entry to `~/Projects/homeofficestack/data/featured-products.json` under `desk_gear`. Required fields:
- `slug`, `name`, `asin`, `category`, `category_label`, `price`
- `rating_stars`, `rating_value`, `review_count`
- `tagline`, `amazon_image`, `date_published`
- `verdict`, `specs`, `brand`, `what_we_liked`, `what_could_be_better`, `performance`, `who_this_is_for`, `bottom_line`

### Step 2 — Generate the review page

```bash
cd ~/budget-tech-picks
python3 scripts/render_review.py <slug>
```

This reads from `data/featured-products.json` and outputs `reviews/<slug>.html`.

### Step 3 — Regenerate ALL site pages

```bash
cd ~/budget-tech-picks
python3 scripts/regenerate_site.py
```

This propagates the new product across:
- `index.html` — homepage picks grid
- `categories/desk-gear.html` — all products grid
- `categories/<category>.html` — category-filtered grid
- Footer links — automatically

### Step 4 — Validate

```bash
cd ~/budget-tech-picks
./scripts/validate-review.sh reviews/<slug>.html
```

### Step 5 — Publish

```bash
cd ~/budget-tech-picks
./scripts/publish-review.sh reviews/<slug>.html "Add review: <Product Name>"
git push origin main
```

### CRITICAL ORDER

1. Add to `featured-products.json` FIRST
2. Run `regenerate_site.py` BEFORE committing review page
3. Validate BEFORE publishing
4. Push last

The system is designed so that `featured-products.json` is the single source of truth. Never edit product cards or grids by hand — always edit the JSON and regenerate.
